## The main findings of the session (details in the stories)

- The game keeps the **pointer position, the map view's origin and the viewed plane** in its own data segment (`DGROUP + 0x78C2`, `+0x6FFE`, `+0xBD86`). No DOSBox change needed.
- The game draws stacks from a picture it built earlier: a record changed by hand (a dead unit, a moved unit) shows as a **ghost** until the map view is nudged, the plane flipped or the turn ended.
- **Unit type names are in the game's memory** (the type table, 198 types, name pointers): nothing from the game is shipped.
- A unit's **weapon quality is the low two bits of `+23`** (0 normal, 1 magic, 2 mithril, 3 adamantium), its **moves left (`+8`) is a signed byte of half-moves** (127 is the top, 63.5 moves), its **enchantments a u32 at `+24`**. Sources: the 2001 save-game page and ReMoM's `s_UNIT` (both in the Evi vault), plus the real game.
- **No mana at End Turn:** the game disbands the wizard's *summoned creatures* ("lack of mana") and dissipates *every unit enchantment*. Ordinary units survive.
- An eliminated wizard (`banish --dead`) is the cracked stone; it survived a turn with nothing coming back. A *banished* wizard casts Spell of Return and can take many turns to come back (Kevin: no need to test).
- A dead unit is swept at End Turn (the live count dropped 147 to 137).

## Things that tripped us up

- The first `live_session.sh` had no writes flag: every write failed with "DOSBox refuses writes" (fixed, Mirror PR 120).
- The Claude Code auto-mode guard blocks a raw script that writes to a running program the first time; Kevin's explicit "yes" lets it through. mompy's own commands were not blocked.
- GitHub's merge button takes minutes to say "clean" after every push, and every push restarts it: batch doc edits into a PR before pushing.
- A `poke` guess that tests the *wrong* thing is easy to run against a real game: `where` and `--dry-run` first; one ambiguity test wrote to a real city before it was caught (and undone).
